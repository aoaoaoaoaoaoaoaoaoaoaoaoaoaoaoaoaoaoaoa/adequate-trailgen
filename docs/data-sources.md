# Data Sources

The app must not swear fealty to one provider. Current ingestion accepts GeoJSON trail/network layers plus GPX, GeoJSON, KML, KMZ, and CSV route files, including user exports from apps such as AllTrails when the user supplies them.

`trailgen init <project> --name "..." --bbox west,south,east,north` persists a project area of interest. `trailgen discover <project>` then scans `sources/` for local files and writes `sources/manifest.json`, including implemented adapters, planned seams, local source candidates, provider-neutral acquisition recommendations, and a coverage ledger for trail network, DEM, terrain/surface, access, closure, road, hydrology, and seed-route inputs. Each recommendation records priority, compatible adapter IDs, suggested local paths, search terms, acceptance criteria, rationale, and the AOI bounds; `discover --bbox ...` can override the config AOI for one pass. The recommendations do not crown a single provider. They are an inspectable shopping list for official GIS portals, OSM-derived extracts, DEM catalogs, land-cover layers, closure feeds, and personal route archives.

The coverage ledger evaluates each recommendation against the candidate set as `satisfied`, `missing`, or `planned-adapter-only`. `satisfied` means a matching candidate uses an implemented adapter; `planned-adapter-only` means bytes exist but the normalizer is not implemented yet, such as a GeoTIFF DEM seam before a raster adapter lands. Generated route manifests and Markdown reports include the same coverage summary, so a route can be reproduced together with evidence of which source classes were actually present.

`trailgen cache-source <project> --input URL_OR_PATH --output relative/name.geojson` is the explicit acquisition/cache seam. It copies local files or downloads `http://`/`https://` URLs into `project/sources/`, classifies the cached artifact by filename when possible, records the original input string as `origin`, fingerprints the cached bytes, and updates `sources/manifest.json`. Use `--kind trail-network|seed-route|elevation|terrain|access|closure|road|hydrology` and `--adapter ADAPTER_ID` when an agency filename is ambiguous. Cache outputs are forced to remain relative paths under `sources/`; reproducible projects should build/apply/import from those cached files, not from mutable download locations.

Every source candidate discovered, cached, or consumed by `build`, `apply-*`, or `import-seed` carries byte count plus SHA-256 fingerprint, so later generation manifests can detect source drift instead of trusting filenames. `trailgen verify-sources <project>` recomputes those fingerprints and fails on missing, unfingerprinted, or drifted inputs. Current implemented adapters cover GeoJSON trail/network files, route-derived graph builds from GPX/GeoJSON/KML/KMZ/CSV when no network layer is available, GeoJSON terrain/land-cover/surface overlays, GeoJSON access/closure overlays, GeoJSON road/hydrology context overlays, Arc/Info ASCII Grid (`.asc`) DEM enrichment, plus GPX/GeoJSON/KML/KMZ/CSV seed routes. Route-derived graph builds carry `route-file` / `route-derived-network` provenance and confidence `0.65`; they are useful scaffolds, not a claim that one completed track is an authoritative trail network. `trailgen apply-elevation <project> --source dem.asc` samples a local DEM through `ArcAsciiGrid`, densifies cached graph geometry, records elevation provenance, recomputes ascent/descent/grade, infers terrain where evidence is otherwise weak, and rerates edge difficulty. `trailgen apply-terrain <project> --source terrain.geojson` applies polygon or line terrain overlays using `terrain`, `surface`, `landcover`, or `land_cover` properties, records terrain evidence/provenance, lowers confidence according to overlay confidence, and rerates touched edges. `trailgen apply-context <project> --source roads-or-streams.geojson` applies road and water LineString context layers, counts trail crossings, records crossing provenance, uses road crossings as road-exposure hints, lowers confidence according to context confidence, and rerates touched edges. `trailgen apply-access <project> --source closures.geojson` applies polygon or line closure/access features to the cached graph, records access provenance, lowers confidence according to overlay confidence, and recomputes edge difficulty. `trailgen import-seed <project> --route file.gpx --name "Known Loop"` archives the supplied file under `seeds/imports/`, snaps that archived copy to the current graph, writes `seeds/seeds.json`, records the original source path for human traceability, fingerprints the archived copy, and raises confidence/popularity hints on touched edges. Adapters should normalize into `SegmentDraft`, overlays, or route seeds plus provenance and confidence; provider-native quirks belong at the perimeter.

Processed graph artifacts live under a project `cache/` directory. `trailgen generate` writes `routes/generated.manifest.json`, binding generated routes to the CLI app version, random seed, effective config, `sources/manifest.json` when present, graph summary, exact edge-id sequences, and emitted artifacts. The source manifest is content-addressed by SHA-256 where files are available, and Markdown reports append a source manifest section so provenance is visible without opening JSON. The current solver is deterministic; the seed is still recorded so future stochastic solvers inherit the same reproduction contract.
